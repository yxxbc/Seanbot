# 知识库说明

> 设计/实现说明，随仓库发布；**使用层面**的说明见知识库条目 `SeanbotTools/02-KnowledgeBase.md`。

## 两种知识库

| | 默认路径 | 谁维护 | 能不能写 |
|---|---|---|---|
| **内置**（官方） | `~/.seanbot/kb` | Seanbot 官方，随二进制分发、首次使用时自动释放 | **只读**：`edit` / `bash` 都会拒绝，工具里只能 `kb_list` / `kb_search` |
| **外置**（用户 / agent 自建） | `~/.seanbot/kb-custom` | 用户或 agent 自己 | 可写：`kb_add` / `kb_edit`，也可以直接编辑文件 |

两者路径不同、来源可辨（工具输出里用 `[内置]` / `[外置]` 标注），这样能防止误删误改官方内容。

## 工具与命令

- `kb_list` 列条目、`kb_search` 按正则搜内容、`read` 看全文
- `kb_add` / `kb_edit` 维护外置条目（`kb_edit` 与 `edit` 共用同一套替换引擎：精确优先、`occurrence` 指定第几处）
- `kb_update` = `sean kb update`：取回官方索引与条目，只覆盖有变化的文件，并清理官方已删除的条目
- CLI：`sean kb`（列出）、`sean kb update`（更新）

## 更新机制（内容比对，不看版本号）

- 索引：仓库 `kb/index.json` 列出全部条目路径；数据目录里的每个知识库目录也存一份 `index.json`，记录"最近一次应用成功的清单"
- 地址：默认 `https://raw.githubusercontent.com/yxxbc/Seanbot/main/kb`，可用 `SEANBOT_KB_BASE_URL` 或配置 `[tools.kb] base_url` 覆盖
- 判断"是否最新"：逐条比较远程与本地内容，一致就跳过——不依赖版本号，也不用额外维护哈希
- 释放内置条目时**只补缺失文件**，不覆盖已存在的：否则远程更新过的内容会被旧的内嵌副本顶回去

## 为什么内置目录必须只读

知识库会**编进二进制**，也会被 `kb_update` / `sean kb update` 从官方地址拉取。如果 agent 能改它，用户的改动看起来"生效了"，下一次更新却会被覆盖——不如一开始就拒绝并说明替代做法（写进外置知识库）。

同理，**知识库条目只能引用已提交的路径**（其他 kb 条目、`scripts/`、`prompt/`、源码路径），不能引用只在作者本机存在的目录：条目会随安装分发，别人看不到本地文件（有测试专门守这条）。实现说明类文档在 [docs/design/](../design/)，kb 里只给仓库 URL。

## 与外置知识库、项目指令的分工

- 长期事实（怎么用、约定、边界）→ 外置知识库
- 关于 Seanbot 自身的问题（"它是什么 / 怎么用 / 有哪些命令"）→ 先查内置知识库再回答
- 项目内部约定与技能 → 项目里的 `AGENTS.md` / `CLAUDE.md` 与技能目录，不必重复写进知识库
