# 设计文档（随仓库发布）

这里放**已实现部分**的设计与实现说明，面向二次开发与排查问题的人。使用层面的说明在 [`kb/`](../../kb/)（随二进制分发，`sean kb search` 可查）。

| 文档 | 内容 |
| --- | --- |
| [内核.md](内核.md) | 内核的职责边界：目标与任务状态、消息与工具调用、事件流 |
| [工具说明.md](工具说明.md) | 工具的分层规划（内核层 / 中间层），逐项标注已实现与规划中 |
| [知识库说明.md](知识库说明.md) | 内置与外置知识库的划分、以及"是否需要更新"的判定 |
| [进程清理.md](进程清理.md) | 常驻 bash 会话的清理层次与手工复现实验 |

## 约定

- **代码是权威来源**：这些文档写的是设计意图与脉络，具体行为（参数、默认值、错误文案）以 `crates/` 为准。
- 标「规划中」的都是**还没实现**的东西，别当成现有行为。
- 不随仓库发布的内容（作者笔记、过程文档、未实现构想）在本地 `docs/Seanbot/` 与 `docs/superpowers/`，已被 `.gitignore` 忽略。

## 与知识库的分工

- `kb/` = 给用户和 agent 看的**使用知识**：会编进二进制、也能从远程 `kb/` 更新，所以只能引用已提交的路径。
- `docs/design/` = 给贡献者看的**实现说明**：不参与分发，可以谈内部结构与代码位置。
- 两者都不引用对方不存在的路径：知识库若要指向这里，用仓库 URL 而不是本地路径。
