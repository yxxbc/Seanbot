# 内核（seanbot-core）

> 设计/实现说明，随仓库发布。代码是权威来源：`crates/seanbot-core/`。

内核 = **agent 主循环 + 工具执行 + 会话状态**。它**不接触终端**：对外只有两条边——`AgentEvent` 事件流（mpsc）与 `PermissionHandler` 抽象，所以将来做桌面端可以直接复用同一份内核。

## 现状（已实现）

### 边界与依赖
- 依赖链单向：`seanbot-cli → seanbot-core → seanbot-provider`；内核不认识终端，也不认识 CLI。
- provider 层只做"把消息发给模型、把流式碎片拼成完整工具调用"：内核永远只看到完整的 `ToolCall`（参数是模型给的原始 JSON 字符串，由内核解析）。

### 一轮是怎么跑的
`Agent::run_turn(input, events, cancel)` 就是一轮：

1. 追加用户消息进历史（发出 `MessageAppended`）
2. 请求模型，流式产出推理与正文（`ThinkingStarted` / `ReasoningDelta` / `TextDelta`）
3. 若模型要求调用工具：过黑名单 → 过权限 → 执行 → 把结果作为工具消息写回历史（`ToolStarted` / `ToolFinished`）
4. 没有工具调用则本轮结束（`TurnFinished`，带用量与步数）；一轮最多 50 步

### 必须守住的不变量
- **历史一致性**：每个助手 `tool_call` 都必须有一条对应的工具消息——取消、出错、超步数也一样。少一条，下一轮请求就会被服务端拒绝。
- **请求前缀稳定**：系统提示词在整个会话内逐字节不变（不含时间戳；`/clear` 不重建），历史只追加，工具定义顺序固定（注册表是 `BTreeMap`）。DeepSeek 的前缀缓存靠这个生效，动了就等于每轮全价。
- **内置工具不可改**：注册与内置同名的工具直接报错；`ToolSource` 区分 `Builtin | AgentCreated | Plugin`。
- **黑名单先于权限**：`bash` 的危险命令在问用户之前就被拒，任何模式都绕不过。

### 工具注册
`crates/seanbot-core/src/tools/` 下每个工具实现 `Tool` trait（`spec` / `risk` / `title` / `preview` / `call`），注册表由 `builtin_registry()` 组装，顺序固定。清单见 [工具说明.md](工具说明.md)。

## 目标（部分未落地）

早期设想里内核还要管"目标与任务状态"和"当前上下文"，现在只落了一半：

| 设想 | 现状 |
|---|---|
| 目标与任务状态（总目标、子任务、优先级、成功标准） | **未实现**：目前只有"当前这一轮"，跨轮任务由模型自己在对话里记 |
| 当前上下文（环境、用户约束、正在执行的步骤、重要结论） | **部分**：环境来自系统提示词与 `perceive`，其余靠对话历史 |
| 决策与执行循环（感知 → 思考 → 行动 → 观察 → 修正） | **已实现**：就是上面的主循环，模型自主多步 |
| 工具注册（内置只读、自建可注册、插件可注册） | **部分**：内置已就位；`ToolSource` 三类来源已区分，但"模型自己注册工具"与插件加载都还没做 |
