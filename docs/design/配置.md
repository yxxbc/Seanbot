# 配置

> 本文分两部分：**现状**（已实现，可以照它排查）与**目标设计**（还没实现，别当成现有行为）。
> 字段与默认值以 `crates/seanbot-core/src/config.rs` 为准。

## 现状：文件与保护

- 数据目录 `~/.seanbot/`（`SEANBOT_HOME` 可覆盖），配置在 `config.toml`，权限 `0600`
- 顶层分段：`provider` / `model` / `[providers.*]` / `[agent]` / `[tools.*]` / `[ui]`
- `config.toml` 里含 API key，所以 `read` / `bash` / `edit` **一律禁止触碰它**，报错会说明改用 `config` 工具

## 现状：专属的配置工具 `config`

模型改配置只能走它，而且只能改**白名单**内的键：

| 动作 | 说明 |
|---|---|
| `list` | 列出全部可改键与取值范围 |
| `get <key>` | 读一个键的当前值 |
| `set <key> <value>` | 设置一个键，**立刻对后续调用生效**（工具每次调用读当前值） |
| `unset <key>` | 恢复默认值 |

可改键共 9 个：`agent.max_steps`、`tools.bash.max_timeout`、`tools.bash.max_output`、`tools.bash.max_sessions`、`tools.read.default_lines`、`tools.search.default_results`、`tools.kb.max_results`、`tools.web.max_results`、`tools.web.page_chars`。

**只能手动编辑**（工具会拒绝并说明原因）：`providers.*.api_key`（密钥）、`provider` / `model`（厂商与模型）、`tools.bash.deny`（命令黑名单，改完需重启生效）。

权限上 `set` / `unset` 属于改动类操作：确认模式下要用户点头，`-p` 非交互时默认拒绝（除非 `--yolo`）。

## 目标设计：谁改了配置（未实现）

需求：不管改动来自用户在 CLI / TUI / 桌面端的操作，还是来自 AI 通过 `config` 工具调用，都要能回答**"这次改动是谁做的"**，并留下可追溯的日志。

设计要点：

1. `get_edit_config_operator_id`：在配置写入路径上取本次操作的**操作者标识**——用户交互（CLI / TUI / App）与 AI 工具调用是两类不同来源，各自带 id。
2. **配置审计日志**：每次 `set` / `unset`（以及用户手动保存）写一条记录——时间、操作者 id、来源（CLI / TUI / App / AI 工具）、键、旧值、新值。
3. **默认保留 30 天**，到期滚动清理；保留期将来做成可配置项。
4. **日志不落密钥**：`providers.*.api_key` 这类只记"被改过"，不记录值；日志文件权限同样 0600。

实现建议：操作者 id 放进运行时状态（`RuntimeState`）由各端写入；审计写入挂在"配置保存"这唯一入口上，避免出现"改了但没记"。

**决定**：审计日志**只给用户查**（`sean config log`），不开放给 agent；agent 只通过 `pceive` 看到"本会话由它自己改过的键"。

### 实现细节（待做）

#### 数据与存储

| 文件 | 内容 | 权限 |
|---|---|---|
| `<数据目录>/operator-id` | 安装级操作者 id：首次启动生成 16 字节随机 hex，之后只读 | 0600 |
| `<数据目录>/config-audit.log` | 审计日志，一行一条 JSON（JSONL），只追加 | 0600 |
| `<数据目录>/config-fingerprint` | 最近一次**由我们写入**的 config.toml 内容哈希（16 字节 hex），用于识别外部改动 | 0600 |

审计记录（`AuditEntry`）：

```json
{"at":"2026-09-29T22:41:03+08:00","actor":"agent","source":"tui","operator_id":"9f3c…","session_id":"20260929-224103-a1b2c3","key":"tools.bash.max_timeout","old":600,"new":900}
```

- `actor`：`user`（人在 CLI / TUI / App 里改）/ `agent`（模型通过 `config` 工具改）/ `external`（检测到不是我们写的，只记键名与"变了"）
- `source`：`cli` / `tui` / `app` / `tool`
- `session_id`：agent 改动时带上（能追到具体对话）；用户改动时为 `null`
- 密钥类键（`providers.*.api_key`）的 `old` / `new` 一律写 `"<redacted>"`，只保留键名与"被改过"这一事实

#### 代码结构（改动点）

1. `seanbot-core/src/config.rs`
   - `pub fn operator_id(data_dir: &Path) -> Result<String, ConfigError>`：读/生成 `operator-id`
   - `pub struct AuditEntry` + `pub enum Actor / Source`（serde）
   - `pub fn save_with_audit(&self, path: &Path, ctx: &AuditContext, changes: &[Change]) -> Result<(), ConfigError>`：**唯一写入口**——写 config.toml → 更新 fingerprint → 追加审计（顺带滚动）
   - `pub fn read_audit(data_dir: &Path, since: Option<Duration>) -> Result<Vec<AuditEntry>, ConfigError>`
   - `pub const AUDIT_RETENTION_DAYS: u64 = 30`；滚动在写入时做：按月/按行过滤超期记录后原子重写（日志很小，直接重写最简单）
2. `seanbot-core/src/runtime.rs`：`RuntimeState` 增加 `operator_id: String` 与 `session_config_changes: Vec<String>`（本会话被 AI 改过的键，供 `perceive` 用）
3. `seanbot-core/src/tools/config.rs`：`set` / `unset` 走 `save_with_audit`，`AuditContext { actor: Agent, source: Tool, session_id }`
4. `seanbot-cli/src/tui/mod.rs`（`/mouse` 写 `[ui] mouse`）：`AuditContext { actor: User, source: Tui }`；将来桌面端同理传 `App`
5. `seanbot-cli/src/main.rs`：`sean config log [--since 7d] [--json]`——默认人类可读（时间 / 谁 / 来源 / 键 / 旧 → 新），`--json` 原样输出
6. `seanbot-core/src/tools/perceive.rs`：增一行「本会话由 AI 改过的配置项」；**不读日志文件**，只读 `RuntimeState`
7. 外部改动识别：加载配置时算指纹，与 `config-fingerprint` 不一致且日志里最近一条不是我们刚写的 → 补一条 `actor: external`（只记差异键名）

#### 测试

- `operator_id`：首启生成、二次调用不变、权限 0600
- actor / source 判定：工具改 → `agent+tool`；TUI 改 → `user+tui`
- 脱敏：改 `providers.deepseek.api_key` 时日志里不出现明文（含 `old`）
- 滚动：构造 31 天前的记录，写入后超期行被清理、未超期保留
- 外部改动：直接手改 config.toml 后加载，产生 `external` 记录且不覆盖用户内容
- CLI：`--since` 过滤、`--json` 输出可解析
- 回归：不写审计的路径（例如只读 `get`）不产生日志
